🔒 Our Commitment

For Privacy Shield and Password Manager, the developer does not operate a server that receives your data. Digital Khata is different and uses online services; see the Digital Khata section below.

All settings, preferences, and credentials are stored locally on your device. For browser extensions, this data is stored using built-in storage APIs (chrome.storage.local). For the Android App, your vault and passwords are encrypted locally on the device (per the source reviewed, version TBD by developer: AES-256-GCM, key derived from your master password with PBKDF2-HMAC-SHA256, 600,000 iterations). This data never leaves your device unless you explicitly export it yourself.

We do not collect:

  • ❌ Personal information (name, email, address, etc.)
  • ❌ Browsing history
  • ❌ Usage statistics
  • ❌ Analytics or telemetry
  • ❌ Cookies or credentials
  • ❌ Health, financial, or authentication data
  • ❌ Location data

Privacy Shield and Password Manager: no account is required. Digital Khata requires an account (Firebase Authentication).

📌 What Data Is Stored, And Where

The following data is stored locally on your device:

Data Type Purpose

This data never leaves your device unless you explicitly use the Export Backup feature or the network requests listed on this page (Digital Khata: see its own section). Even then, the exported file is saved on your own device and is not transmitted to us.

🌐 Network Requests Privacy Shield Makes (build 9.7.7)

Source: the developer's build record for 9.7.7, based on a scan of the 9.7.7 source code for fetch, XMLHttpRequest, sendBeacon, WebSocket, EventSource, new Image and setUninstallURL. This page was prepared from that record; the 9.7.7 source itself was not re-reviewed for this website update.

1. Filter List Updates (Automatic)

The extension downloads publicly published ad/tracker block-lists when it starts and on a timer:

  • EasyList — https://easylist.to/easylist/easylist.txt
  • EasyPrivacy — https://easylist.to/easylist/easyprivacy.txt
  • uBlock Origin Annoyances list — https://raw.githubusercontent.com/uBlockOrigin/uAssets/master/filters/annoyances.txt

These are plain downloads (GET requests). No data about you or your browsing is sent in the request, but the hosting servers (easylist.to, GitHub) can see your IP address and browser User-Agent, as with any download.

2. New Tab saved-site logos

From version 9.7.7, the logo of a saved site on the New Tab page is loaded from that site's own /favicon.ico (or a letter avatar is shown). Earlier versions used Google and DuckDuckGo icon services, which received the domain of each saved site; this was removed in 9.7.7.

3. Breach Check (link only)

  • The "Open haveibeenpwned.com" button only opens the haveibeenpwned.com website in a browser tab.
  • The extension does not collect or send any email address and has no API key. No request to the HIBP API is made.
  • An email-based "Breach Alert" with your own API key is not part of 9.7.7 (older versions: TBD by developer).

4. DNS-over-HTTPS setting

  • The default is off. The choices are Off, Cloudflare, Google and Quad9.
  • The extension does not set your DNS itself. Choosing a provider only saves your choice and opens your browser's own settings page (Chrome: chrome://settings/security; Firefox: about:preferences#privacy). You then pick "Use secure DNS" in the browser.
  • The extension does not proxy or see DNS traffic.

5. Links that open only when you click

haveibeenpwned.com (breach button), ramhardamp.github.io/bsrpro (developer page) and your chosen search engine from the New Tab search box.

No analytics or telemetry

The 9.7.7 code scan found no analytics, telemetry or crash-report endpoint, and no use of sendBeacon, WebSocket, EventSource or setUninstallURL. No external fonts, scripts, stylesheets or images are loaded by the extension's pages. This is a statement about the source code scan; the store listings are separate.

📒 Digital Khata

Digital Khata works differently from the Password Manager and the browser extensions. It uses online services. This section is based only on the part of the Digital Khata code reviewed so far (dashboard.html). It is not a complete description of Digital Khata's data handling.

Data / ServiceWhat the code shows
Firebase AuthenticationShop owner sign-in (email)
Cloud FirestoreShop details (shop name, phone, UPI ID); customers (name, phone, email, balance); transactions (type, amount, note, date)
Public customer view (publicViews)When a customer view link is created, a copy of the shop name, phone, email and UPI ID, the customer's name and phone, the balance and the transaction history is written to a separate Firestore document identified by a token in the link
EmailJS (third party)When a transaction email is sent, the customer's name and email, shop name and email, amount, note, date, balance and view link are sent to EmailJS from the app
SMS / WhatsAppMessage text is passed to the phone's SMS or WhatsApp app. The Android app also has a direct-SMS option (enabled by default in the app configuration)
Third-party scriptsLoaded from gstatic.com (Firebase), cdn.jsdelivr.net (EmailJS) and cdn.sheetjs.com (Excel export)

Unverified (TBD by developer): who can read a public view link (Firestore security rules), data retention and deletion, Cloud Functions, the sign-in and sign-up pages, Android native plugins, and EmailJS data retention.
